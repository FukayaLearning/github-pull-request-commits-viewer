# Local PR and MR Commits Viewer 要求仕様書

## ＜機能要求＞

### リポジトリ情報取得, PR連携, コミット差分取得: 上位要求 R01

**要求**: ローカルのGitリポジトリおよびGitHubのプルリクエストから、比較対象ブランチ、コミット履歴・メタデータ、およびコミット単位の差分データを取得して提供する。
**理由**: 1タスク＝1コミットで積まれた履歴をローカル環境で高速かつ構造的に検査するためのデータ基盤が必要であるため。
**説明**: ローカル環境にインストールされたGitコマンドおよび任意のGitHub CLIを利用して動作する。

#### ＜ターゲットおよびPR情報の取得＞

##### 下位要求 R01-01

**要求**: 対象ローカルGitリポジトリのリポジトリ名、現在のブランチ名、および利用可能なブランチ一覧を取得する。
**理由**: ユーザーが現在レビュー対象としているリポジトリとブランチの状態を即座に把握できるようにするため。
**説明**: サーバー起動時に指定されたローカルディレクトリを対象とする。

###### ＜リポジトリ状態応答＞

- ■■■ **S01-01-01**: `GET /api/repo-info` の要求に対し、対象ディレクトリのGitリポジトリ名、現在のチェックアウトブランチ名、デフォルトベースブランチ候補（`main` または `master` 等）、およびローカル・リモートブランチ一覧をJSON形式で返却すること。
- ■■■ **S01-01-02**: 対象ディレクトリが有効なGitリポジトリでない場合は、HTTPステータス400または500とともに原因を示すエラーメッセージをJSON形式で返却すること。

##### 下位要求 R01-02

**要求**: GitHub上のオープンなプルリクエスト一覧を取得し、取得できない場合はローカルブランチ比較へフォールバックする。
**理由**: PR番号を選ぶだけで比較元（base）と比較先（head）を自動設定でき、かつオフライン時やPR作成前でもローカルブランチ間の比較を継続できるようにするため。
**説明**: GitHub CLIが未インストールまたは未認証の環境も考慮する。

###### ＜PR一覧応答とフォールバック＞

- ■■■ **S01-02-01**: `GET /api/prs` の要求に対し、GitHub上のオープンPR一覧（PR番号、タイトル、headRefName、baseRefName）をJSON配列で返却すること。
- ■■■ **S01-02-02**: GitHub CLIが未認証・未導入・ネットワーク不可、またはオープンPRが0件の場合でもエラー停止せず、フォールバック状態を示すフラグと空配列およびローカル比較用のデフォルトbase/head候補を返却すること。

#### ＜コミット履歴解析およびDiffデータの取得＞

##### 下位要求 R01-03

**要求**: 指定されたベースブランチからヘッドまでのコミット一覧を取得し、コミットメッセージ本文からタスク情報や実行コマンド等のメタデータを構造化して抽出する。
**理由**: 各コミットが「どのOpenSpecタスクに対応するか」「コマンドによる一括変更か手動変更か」をUI側で視覚的に判別・強調表示できるようにするため。
**説明**: コミットメッセージ内のGit Trailersや定型プレフィックスを解析対象とする。

###### ＜コミット一覧とメタデータ解析＞

- ■■■ **S01-03-01**: `GET /api/commits?base=<base>&head=<head>` の要求に対し、`base..head` 範囲のコミット一覧（SHA、短縮SHA、件名、本文、作成者、日時）を時系列順のJSON配列で返却すること。
- ■■■ **S01-03-02**: コミットメッセージ本文から `Issue:`, `Task:`, `Why:`, `What:`, `Executed-Command:`, `Verification:` の各メタデータ項目を抽出し、構造化フィールドとして各コミットオブジェクトに含めること。
- ■■■ **S01-03-03**: 抽出されたメタデータおよびコミット情報に基づき、変更種別（`Executed-Command` が存在し `"manual"` 以外の場合はコマンド一括変更、テスト関連の場合はテスト追加、それ以外は手動実装）の分類情報を付与すること。

##### 下位要求 R01-04

**要求**: 指定されたコミットSHAにおける変更ファイル一覧（追加・削除行数）およびUnified Diff文字列を取得する。
**理由**: 選択した単一コミットの変更範囲とコード差分を正確にレンダリングするため。
**説明**: 空白変更の無視オプションにも対応する。

###### ＜コミット単位Diff応答＞

- ■■■ **S01-04-01**: `GET /api/commits/<sha>/diff` の要求に対し、当該コミットで変更されたファイル一覧（ファイルパス、変更ステータス、追加行数、削除行数）とUnified Diff全文をJSON形式で返却すること。
- ■■■ **S01-04-02**: クエリパラメータ `ignore_whitespace=true` が指定された場合、空白変更を無視したUnified Diffを生成して返却すること。

### 3ペイン画面表示, コミット切り替え, Diff閲覧: 上位要求 R02

**要求**: 1画面の3ペインレイアウト上で比較対象の選択、コミット一覧の高速切り替えと確認済みチェック、およびコミット文脈とシンタックスハイライト付きDiffの閲覧を提供する。
**理由**: ページリロードや画面遷移の待ち時間をなくし、コミット単位の文脈とコード差分を連続してストレスなくレビューできるようにするため。
**説明**: ブラウザ上で動作する単一ページUIとして構成する。

#### ＜ターゲット選択とコミット一覧ナビゲーション＞

##### 下位要求 R02-01

**要求**: ヘッダー領域に現在のリポジトリ・ブランチ情報を表示し、プルリクエストまたは比較元ベースブランチを選択してコミット一覧を切り替えられるようにする。
**理由**: レビュー対象のPRや比較範囲を画面上部から即座に指定・変更できるようにするため。
**説明**: PR選択時とブランチ直接指定時の双方に対応する。

###### ＜ターゲット選択ヘッダー表示＞

- ■■■ **S02-01-01**: 画面上部のヘッダーに現在のリポジトリ名とブランチ名を表示し、オープンPR一覧のドロップダウン選択または比較元ベースブランチ（`main` 等）と比較先ブランチ（`HEAD` 等）の直接指定UIを提供すること。
- ■■■ **S02-01-02**: PRまたは比較ブランチが変更された際、ページ全体をリロードすることなく対象範囲のコミット一覧を再取得して左ペインを更新すること。

##### 下位要求 R02-02

**要求**: 左ペインにコミット一覧を時系列表示し、変更種別バッジの表示、キーボードによる高速切り替え、およびローカルでの確認済み（Reviewed）チェック管理を提供する。
**理由**: 機械的変更と手動実装を一目で区別しつつ、キーボード操作のみで次々とコミットを検査し、どこまでレビューしたかの進捗を保持するため。
**説明**: 確認済み状態はブラウザのローカルストレージに保存する。

###### ＜コミット一覧メニューと操作＞

- ■■■ **S02-02-01**: 左ペインにコミット一覧をリスト表示し、メタデータ分類に応じて「🤖 コマンド一括変更（Command）」「✍️ 手動実装（Manual）」「✅ テスト追加（Test）」等の視覚的バッジおよびOpenSpecタスク識別子を表示すること。
- ■■■ **S02-02-02**: キーボードの `j` / `k` キーまたは `↓` / `↑` 矢印キーの押下により、ページリロードなしで選択中のコミットを前後に即座に切り替えられること（入力フォームへのフォーカス時を除く）。
- ■■■ **S02-02-03**: 各コミット項目に「確認済み（Reviewed）」チェックボックスを設け、チェック状態をコミットSHA単位でブラウザの `localStorage` に永続化するとともに、全体のレビュー進捗件数（確認済み数／全コミット数）を表示すること。
- ■■■ **S02-02-04**: キーボードショートカット（例: `r` キーまたはスペースキー）でも現在選択中のコミットの「確認済み（Reviewed）」状態をトグルできること。

#### ＜コミット文脈表示と高視認性Diffビューア＞

##### 下位要求 R02-03

**要求**: メインペイン上部に、選択中コミットの目的、紐づくOpenSpecタスク内容、および実行コマンド全文をカード形式で強調表示する。
**理由**: コード差分を読む前に「なぜこのコミットが行われたか」「どのコマンドの実行結果か」を瞬時に把握できるようにするため。
**説明**: メタデータが存在しない項目は控えめに表示または省略する。

###### ＜コミットサマリヘッダー表示＞

- ■■■ **S02-03-01**: メインペイン上部のサマリカードに、コミット件名、SHA、作成者・日時、コミットの目的（`Why` / `What` または本文）、紐づくOpenSpecタスク情報（`Task`）、検証結果（`Verification`）を整理して表示すること。
- ■■■ **S02-03-02**: `Executed-Command` が存在するコミットでは、実行されたコマンド全文を等幅フォントの強調ブロックで上部に表示し、機械的変更であることを明示すること。

##### 下位要求 R02-04

**要求**: メインペイン下部に変更ファイル一覧とシンタックスハイライト付きのDiffビューアを表示し、Split（左右分割）/ Unified（統合）表示および空白無視オプションを切り替えられるようにする。
**理由**: 変更されたファイル構造を俯瞰しつつ、好みの表示形式でコード差分を快適に読み進められるようにするため。
**説明**: 変更ファイル一覧のクリックで該当ファイルの差分箇所へ移動できるようにする。

###### ＜変更ファイルツリーとDiffレンダリング＞

- ■■■ **S02-04-01**: 選択したコミット内で変更されたファイル一覧（ファイルパス、追加行数 `+N`、削除行数 `-N`）を表示し、ファイル名をクリックすると該当ファイルのDiffセクションへスクロールまたはフォーカス移動できること。
- ■■■ **S02-04-02**: Unified Diffデータをもとにシンタックスハイライト付きのDiffビューを描画し、UI上のトグル操作で「Split（左右分割）」と「Unified（統合）」の表示モードを即座に切り替えられること。
- ■■■ **S02-04-03**: UI上のチェックボックス操作により「空白変更を無視（Ignore Whitespace）」の有効・無効を切り替え、差分表示を更新できること。

## ＜非機能要求＞

### ゼロ依存起動, ローカル即時実行: 上位要求 R03

**要求**: 外部パッケージのインストールやフロントエンドのビルド工程を必要とせず、標準のPython実行環境のみで任意のローカルGitリポジトリに対して即座に起動できるようにする。
**理由**: WindowsやUbuntu等のローカル開発環境において、仮想環境構築やパッケージ導入の手間なく最小のメモリ・起動時間でいつでも使えるようにするため。
**説明**: Python 3標準ライブラリと静的Webアセットで構成する。

###### ＜起動構成と環境互換性＞

- ■■■ **S03-01**: バックエンドはPython 3標準ライブラリのみで動作し、`pip install` や `npm install` 等の事前パッケージインストールなしに単一コマンド（例: `python3 server.py`）で起動できること。
- ■■■ **S03-02**: コマンドライン引数（`--repo <path>` や `--port <port>`）または環境変数（`REPO_PATH`, `PORT`）によって対象ローカルGitリポジトリのパス（省略時はカレントディレクトリ）と待受ポートを指定できること。
