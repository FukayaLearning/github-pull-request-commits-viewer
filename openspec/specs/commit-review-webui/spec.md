# commit-review-webui Specification

## Purpose

ブラウザ上で動作するビルドレスな3ペイン構成のWeb UIにより、PRおよび比較ブランチの選択、変更種別バッジ付きコミット一覧の高速切り替えと確認済み進捗管理、およびコミット文脈サマリとSplit/Unified対応Diffビューアを提供する。

## Requirements

### Requirement: ヘッダーでのPRおよび比較ブランチ選択UI
**USDM**: R02-01
フロントエンドは画面上部のヘッダーに現在のリポジトリ名とブランチ名を表示し、オープンPRのドロップダウン選択または比較元ベースブランチ・比較先ブランチの直接指定によって、ページリロードなしにコミット一覧を切り替えられなければならない（SHALL）。

#### Scenario: [S02-01-01] ヘッダーでのリポジトリ情報とターゲット選択UIの表示
- **WHEN** ユーザーがWeb UIをブラウザで開く
- **THEN** ヘッダーにカレントリポジトリ名・ブランチ名が表示され、オープンPR選択ドロップダウンおよび `base` / `head` ブランチ指定コントロールが表示される

#### Scenario: [S02-01-02] PRまたは比較ブランチ変更時の非同期コミット一覧更新
- **WHEN** ユーザーがヘッダーで別のPRを選択するか比較元ベースブランチを変更する
- **THEN** ページ全体をリロードすることなく `/api/commits` が再要求され、左ペインのコミット一覧と先頭コミットの詳細表示が更新される

### Requirement: 左ペインのコミット一覧メニュー・キーボード操作・確認済み進捗管理
**USDM**: R02-02
フロントエンドは左ペインにコミット一覧を時系列表示し、変更種別バッジの表示、`j`/`k` または上下矢印キーによる即時コミット切り替え、および `localStorage` を用いたコミットSHA単位の「確認済み（Reviewed）」チェック保存と進捗表示を提供しなければならない（SHALL）。

#### Scenario: [S02-02-01] 変更種別バッジとタスク識別子付きのコミット一覧表示
- **WHEN** コミット一覧データが左ペインに読み込まれる
- **THEN** 各コミット項目に分類に応じたバッジ（🤖 Command / ✍️ Manual / ✅ Test 等）とOpenSpecタスク識別子（存在する場合）が視覚的に区別して表示される

#### Scenario: [S02-02-02] キーボードショートカットによる高速コミット切り替え
- **WHEN** 入力フォームにフォーカスがない状態でユーザーが `j` / `k` キーまたは `↓` / `↑` 矢印キーを押下する
- **THEN** ページ遷移なしに選択コミットが次または前のコミットへ即座に切り替わり、メインペインの文脈カードとDiff表示が更新される

#### Scenario: [S02-02-03] 確認済みチェックボックスのlocalStorage永続化と進捗表示
- **WHEN** ユーザーがコミット項目の「確認済み（Reviewed）」チェックボックスをオンまたはオフにする
- **THEN** 当該コミットSHAの確認済み状態が `localStorage` に保存され、ブラウザ再読み込み後も保持されるとともに確認済み件数カウンタが更新される

#### Scenario: [S02-02-04] キーボード操作による確認済み状態のトグル
- **WHEN** コミットが選択されている状態でユーザーが `r` キーを押下する
- **THEN** 現在選択中のコミットの「確認済み（Reviewed）」チェック状態が反転し、`localStorage` と進捗表示が即座に更新される

### Requirement: コミットの目的・タスク・実行コマンドのサマリカード表示
**USDM**: R02-03
フロントエンドはメインペイン上部にコミットサマリカードを配置し、コミットの目的（`Why` / `What`）、紐づくOpenSpecタスク内容（`Task`）、検証内容（`Verification`）、および実行コマンド全文（`Executed-Command`）を強調表示しなければならない（SHALL）。

#### Scenario: [S02-03-01] コミット文脈メタデータのカード表示
- **WHEN** ユーザーが左ペインで任意のコミットを選択する
- **THEN** メインペイン上部のカードにコミット件名、SHA、作成者・日時、および抽出された `Task`・`Why`・`What`・`Verification` メタデータが構造化されて表示される

#### Scenario: [S02-03-02] 実行コマンド全文の強調表示
- **WHEN** 選択されたコミットに `Executed-Command` メタデータが含まれている
- **THEN** サマリカード上部に実行されたコマンド全文が等幅フォントの強調ブロックとして表示される

### Requirement: 変更ファイル一覧とSplit/Unified切替対応Diffビューア
**USDM**: R02-04
フロントエンドはメインペイン下部に変更ファイル一覧とシンタックスハイライト付きのDiffビューアを表示し、ファイルクリックによる該当箇所へのジャンプ、Split（左右分割）/ Unified（統合）表示の切り替え、および空白無視オプションの切り替えを提供しなければならない（SHALL）。

#### Scenario: [S02-04-01] 変更ファイル一覧の表示と該当Diffへのスクロール移動
- **WHEN** 選択されたコミットのDiffデータが読み込まれ、ユーザーが変更ファイル一覧内のファイル名をクリックする
- **THEN** 各ファイルの追加・削除行数が表示され、クリックしたファイルのDiffブロック位置へ画面がスクロール移動する

#### Scenario: [S02-04-02] Split表示とUnified表示の即時切り替え
- **WHEN** ユーザーがDiffビューア上部の表示形式トグルで「Split」または「Unified」を選択する
- **THEN** 現在のコミットのDiffが選択された形式（左右分割または統合表示）かつシンタックスハイライト付きで即座に再描画される

#### Scenario: [S02-04-03] 空白変更無視オプションの切り替え
- **WHEN** ユーザーがDiffビューアの「空白無視（Ignore Whitespace）」チェックボックスを切り替える
- **THEN** `ignore_whitespace` パラメータ付きでDiffデータが取得・再描画され、インデントや空白のみの変更が除外または復元される
